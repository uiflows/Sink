# 运维操作手册

两套实例使用同一固定版本代码，分别绑定自己的 D1、KV、Analytics 和私有 R2；通过 Git 开发分支触发独立云端构建。实际账号、资源标识、版本及现场验收结果保存在本地阶段报告，不将私有清单发布到公共仓库。master 仍未合并，正式短域名未绑定。

每次更新先核实目标账号、远端 commit、实例映射、迁移记录和备份。先测试，再发布；保留 Worker 版本标识。数据库结构变更必须单独评估兼容性，代码回滚不等于数据库恢复。部署后的脚本只更新日志设置并读回确认查询参数脱敏，不覆盖运行密钥。

## 云端健康检查

构建变量 `DEPLOY_HEALTH_ORIGIN` 启用对应实例的定时健康检查，必须是管理员核实的 HTTPS 源站地址。品牌实例在每小时第 2、12、22、32、42、52 分钟执行，营销实例错开 5 分钟。原有每日 00:00 UTC 的自动快照保持独立，健康检查不会额外生成每日快照。Cron 的传播和执行以 Cloudflare 实际记录为准。

每轮执行 D1 表读取、KV 状态读取/写入、每日 R2 快照新鲜度、公共 DNS、HTTPS 首页和 Analytics 查询。最新快照必须在 26 小时以内；读取截断或没有每日文件不能算通过。DNS 至少有一个公共 A 或 AAAA 地址，首页必须直接返回 200。健康请求不自动跟随跳转，设置有限超时，不保存目标地址、Token 或供应商异常正文。

同一检查连续两轮失败后记录 incident，持续故障最多每 6 小时再次写入错误日志；现有按实例区分的 Cloudflare 错误邮件策略负责通知。全部故障恢复后记录 recovered。KV 读写故障会立即写入错误日志，因为状态不可用时无法可靠执行连续失败判断。KV 为最终一致存储，不是严格的全球事件锁。

最新检查及最近 20 个 incident/recovered 事件保存在本实例 KV；7 天无新检查会过期。`GET /api/health` 返回检查状态及是否已超过 30 分钟，`POST /api/health/check` 可人工执行一次；两者均沿用管理员鉴权，手动执行受写入限流保护，响应禁止缓存。未配置的能力明确显示 not-configured。

若配置 `NUXT_HEALTH_CANARY_SLUG` 与 `NUXT_HEALTH_CANARY_TARGET`，可检查专用测试短链的状态码与 Location。最终目标检查还要求该主机存在于 `NUXT_SERVER_FETCH_ALLOWED_HOSTS` 精确可信列表，仅接受直接 2xx；不跟随多层重定向。配置前必须核实目标控制权和 DNS；本项目不提供 DNS 固定或重绑定防护保证。当前未配置专用短链，不能将其描述为已覆盖所有业务链接。短链探测可能写入测试访问统计，应使用专门的合成测试链接。

## 覆盖边界与告警

这是同一 Worker 内的依赖自检，不是独立网络的外部可用性监测。Worker 被删除、账号故障、调度完全停止时，自检本身无法发出通知；独立心跳监测仍待补齐。HTTPS 握手成功不等于已取得证书到期日期。正式域名、注册到期、平台信誉、用量异常、Webhook 渠道和外部心跳尚未全部验收。恢复事件保留在状态及普通日志中，目前不会通过仅匹配 error 的邮件策略发送恢复邮件。

每日快照失败或前置迁移未完成均产生结构化错误日志，不再静默当作成功。原生错误邮件策略已完成服务端测试发送，收件箱送达仍需独立证据。未配置的 Webhook 不显示已发送，也不创建 Codex 本地定时任务充当云端依赖。

现有公开安全检查不代表第三方社交平台内部信誉。P0 全部验收通过前不绑定正式推广域名、不对外推广。仅删除带有本轮明确标记的测试链接，保留所有真实业务记录。
