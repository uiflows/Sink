# 安全与权限

两个实例的登录和分析读取凭据必须独立；匿名请求不能创建短链。分析读取凭据只授予目标账号 Analytics Read，这不等于数据集级 ACL。

## 写入目标与服务端抓取

创建、编辑、导入以及 Apple、Google、地区跳转字段使用同一公共 HTTP/HTTPS 目标校验。拒绝危险协议、嵌入账号密码、localhost、私有和保留 IP 地址以及常见内网后缀。历史记录仍可读取、导出和删除；重新写入必须通过新校验。

服务端元数据抓取、链接检查和反向代理默认不向任意目标发起请求。仅管理员通过私有运行变量 `NUXT_SERVER_FETCH_ALLOWED_HOSTS` 设置的精确可信主机可被请求，使用逗号分隔，不继承子域名。仅允许标准 HTTP/HTTPS 端口，禁用自动跟随重定向。启用抓取前须确认可信域名的 DNS 和服务控制权；此策略不是 DNS 解析结果固定或重绑定防护保证。普通短链重定向不需要抓取白名单。

默认空白名单时，链接检查会明确返回不允许服务端检查；AI 元数据抓取与反向代理也不能访问任意站点。这是安全限制，保留原有后台与接口。

检查命令：`pnpm test:deploy`、`pnpm test:security`、`pnpm types:check`、`pnpm build`。完整 Workers 测试池仍需独立验证，单元测试通过不代表线上验收完成。

## 仍需完成的验收

发布后验证线上写入拒绝、抓取限制、频率限制与操作审计。

实例部署策略设置独立的 Workers Rate Limiting 绑定：每个已认证身份、每个 Cloudflare 位置每 60 秒允许 120 次非只读 API 请求；MCP 通过 POST 调用，读取工具也计入。导入仍受原版每请求 100 条上限约束。该限流为边缘最终一致计数，不是全球精确配额；超限返回 429 与 Retry-After，要求启用时缺少绑定返回 503。

创建、更新、导入和删除在 D1 操作成功后记录结构化日志，包含短码、身份、操作、时间与请求标识，不含目标 URL 或密钥。部署启用全部应用日志采样并关闭常规调用日志和追踪，降低无关日志量。Workers Logs 有平台保留期限；此记录不是永久不可篡改审计，需按实际使用量另行评估归档。恶意软件和钓鱼识别需要可用的安全数据源或人工审核；普通 HTTP 检查不能证明网址安全。P0 安全验收完成前不对外推广。

部署规则禁止误绑正式域名、要求显式账号和资源归属检查；AI 默认关闭。凭据不写入 Markdown、日志或 Git。正式域名、付费变更和现有生产系统修改需要用户明确授权。

## 写入时的网址风险策略

平台部署配置启用 `NUXT_TARGET_RISK_CHECK=true`。创建、编辑及批量导入均在持久化之前检查主目标、Apple、Google 和所有地区目标。调用方提交 `unsafe=false` 不能绕过该策略；原版 unsafe 警告页继续独立工作。历史链接仍可读取、导出和删除，重新写入时执行当前策略。

查询仅把目标主机名发送到固定的 Cloudflare 安全 DNS 解析器，同时查询 A 和 AAAA；不会请求目标网页、URL 路径或查询参数。命中恶意软件或钓鱼拦截地址时拒绝写入，解析结果包含私有/保留地址时也拒绝。安全来源不可用时返回 503，要求稍后重试或人工核实，不自动批准。每个请求最多检查 16 个不同主机，同一主机复用检查结果；更多目标应拆分批次。

`NUXT_TARGET_ALLOWED_HOSTS` 是可选的精确主机批准名单，非空时只接受列表内的主机；`NUXT_TARGET_DENIED_HOSTS` 是精确拒绝名单，拒绝规则优先。不接受通配符，不继承子域名，实际名单只留在实例运行配置中。裸 IP 目标无法进行域名信誉判断，需由管理员核实后明确加入批准名单。

人工流程：先记录业务归属、目标主机、用途与审核依据；确认目标合法且受信任后再更新对应实例的批准名单。收到平台限制或安全通知后，登记原始通知、发生时间和申诉状态，必要时将主机加入拒绝名单。误报应通过服务商官方渠道核实，不采用轮换域名或隐藏目标绕过限制。

这属于域名级安全筛查，不能识别所有恶意 URL 路径、内容变化、违法内容或第三方平台内部信誉，也不提供 DNS 固定/重绑定防护保证。管理员仍需审核业务目标，名单命中不能被当作完整合法性证明。

参考：[Cloudflare 安全 DNS 与官方过滤测试域名](https://developers.cloudflare.com/1.1.1.1/setup/)。线上测试仅使用该文档列出的合成测试域名，不访问真实恶意内容。
